VS Code Extension Tutorial

AI-Native DevOps

A guided tutorial for using the AI-Native DevOps VS Code extension — your control panel for navigating the 11-phase software delivery lifecycle with Claude, OpenAI Codex, or GitHub Copilot.

Overview

The AI-Native DevOps extension brings a structured, policy-governed AI workflow directly into VS Code. Instead of asking AI for ad-hoc help, you work through eleven well-defined lifecycle phases — from planning and design all the way through incident response — each backed by curated prompts, entry checklists, and expected output artifacts.

The governing principle is autonomous execution with policy-controlled human governance: AI agents draft, propose, and automate; humans review, approve, and merge. Nothing goes to production without a traceable record.

What it does

Guided phase navigation

Open the guide, prompt, and checklist for whichever lifecycle phase you are in — directly from the sidebar.

What it does

AI-powered actions

Run phase-aware prompts against Claude, OpenAI, or GitHub Copilot with a single click.

What it does

Artifact scaffolding

Generate the required output files for each phase so nothing is accidentally skipped.

What it does

Webhook automation

Process GitHub events from a local queue and trigger the right agent for each event type.

Installation

1

Prerequisites

Make sure you have VS Code 1.85 or newer installed. The extension requires a workspace folder open (your product repository).

2

Install the VSIX package

The extension ships as a pre-built .vsix file in the repository.

# From the repository root
code --install-extension vscode-extension/ai-native-devops-0.1.9.vsix

Alternatively, open VS Code → Ctrl+Shift+P → Extensions: Install from VSIX… and select the file.

3

Open your repository

Open the folder that contains your project (or this reference repository itself) in VS Code. The extension activates automatically when VS Code finishes loading.

4

Verify activation

Look for the AI-Native DevOps icon in the Activity Bar on the left side of VS Code. Click it to open the Lifecycle Phases sidebar.

💡

Development build: If you want to build from source, run npm install && npm run compile inside vscode-extension/, then press F5 in VS Code to launch an Extension Development Host.

Choose an AI Provider

Before running any prompts, tell the extension which AI backend to use. Open the Command Palette (Ctrl+Shift+P) and run:

AI DevOps: Select AI Provider

Three providers are available:

ProviderModelKey required?Best for
GitHub Copilot Copilot Chat No — sign in to Copilot in VS Code Teams already on a Copilot subscription
Anthropic Claude claude-3-5-sonnet or newer Yes — Anthropic API key (sk-ant-…) Reasoning-heavy tasks: planning, architecture, security, incidents
OpenAI / Codex gpt-4o or any OpenAI model Yes — OpenAI API key (sk-…) Implementation and code generation tasks

API keys are stored in VS Code Secret Storage — they are never written to disk or exposed to your repository.

ℹ️

You can switch providers at any time. The selection is stored per-machine, not per-workspace.

Lifecycle Sidebar

Click the AI-Native DevOps icon in the Activity Bar to open the sidebar. You will see a tree view called Lifecycle Phases listing all eleven phases in order.

Each phase entry has three inline action buttons:

  • Open Phase Guide — opens the rich webview for that phase
  • Run AI Prompt — prompts the AI for that phase immediately
  • Open Checklist — opens the interactive checklist panel
💡

If you click a button without selecting a phase first, a quick-pick menu appears so you can choose the phase you want.

Phase Guides

A Phase Guide is a tabbed webview panel that consolidates everything you need for a single lifecycle phase in one place.

Opening a phase guide

  1. Click a phase in the sidebar or run AI DevOps: Open Phase Guide from the Command Palette.
  2. The panel opens with four tabs: Guide, Requirements, AI Prompt, and Checklist.

Tabs inside the panel

Tab 1

Guide

The full phase documentation rendered as HTML — objectives, activities, responsibilities, and links to related policies.

Tab 2

Requirements

Required input files and expected output artifacts. Missing outputs appear with a one-click Create button to scaffold them.

Tab 3

AI Prompt

The curated phase prompt pre-loaded into a text area. Edit if needed, then click Run to send it to your selected AI provider.

Tab 4

Checklist

The phase checklist embedded inline. Check off items as you complete them; state is persisted across sessions.

ℹ️

You can also run AI DevOps: Open AI DevOps Dashboard — it opens the phase guide for the phase you are currently working on.

AI Prompts

Each lifecycle phase ships with a curated prompt that tells the AI exactly what role to play, what to read, and what to produce.

Running the default phase prompt

1

Run AI DevOps: Run AI Prompt for Phase from the Command Palette or click the play button next to a phase in the sidebar.

2

An input box appears. Leave it blank and press Enter to use the default phase prompt, or type an additional instruction to augment it.

3

The Phase Guide panel opens (or focuses) and streams the AI response into the AI Prompt tab in real time.

What makes a good phase prompt?

The built-in prompts follow this structure — use the same pattern for custom instructions:

Context:
  <repository path, issue reference, logs, constraints>

Task:
  <what the AI should produce for this phase>

Requirements:
  - Produce structured Markdown output
  - State all assumptions explicitly
  - Identify risks and mitigations
  - Include recommended next steps
  - Do not invent facts not present in the context

Output Format:
  <table | checklist | ADR | PR summary | postmortem | …>

Phase Checklists

Every phase has an entry checklist, an execution checklist, and an exit checklist. These ensure the right inputs are ready before work starts and the right artifacts exist before handing off to the next phase.

Opening a checklist

Run AI DevOps: Open Phase Checklist from the Command Palette, or click the checklist icon next to a phase in the sidebar.

Using the checklist panel

  • Check items off as you complete them. Progress is saved automatically.
  • The progress bar at the top shows how much of the phase is done.
  • Items marked as required must be completed before the phase can exit.
  • Use the Reset button to clear all items when starting a fresh iteration.
⚠️

Don't skip checklists. Exit criteria are the handoff contract between phases. Skipping them is the most common cause of regressions and missed security gates.

Custom Prompts

Need to ask the AI something that doesn't fit the default phase prompt? Use the custom prompt command to send any text to any phase's context.

1

Run AI DevOps: Run Custom Prompt from the Command Palette.

2

A quick-pick menu lists all 11 phases. Select the phase most relevant to your question — this loads the right agent context.

3

Type your custom prompt in the input box and press Enter. The AI responds in the Phase Guide panel.

Agent Automation Flow

Agent automation lets you trigger a full structured AI workflow for a phase with a specific trigger — for example, a new GitHub issue, a CI failure, or a security alert.

How to run it

Run AI DevOps: Run Agent Automation Flow from the Command Palette.

  1. Select the lifecycle phase (e.g., Code, Test, Security).
  2. Select a trigger type matching the event (issue opened, CI failed, alert fired, …).
  3. The extension builds an automation prompt that combines the phase spec, agent role, and trigger context, then runs it against your AI provider.

Trigger types

security_alertSecure / ComplySummarizes the finding and recommends remediation
deploy_completeDeploy / MonitorValidates SLOs and generates a deployment summary
incident_openedIncident / LearnStarts a probable timeline, RCA hypothesis, and action items

Scaffold Agent Artifacts

Each phase has a set of required output artifacts — documents that must exist before the phase can hand off. Scaffolding creates stub files for all of them so you never start from a blank page.

How to scaffold

1

Run AI DevOps: Scaffold Agent Artifacts from the Command Palette.

2

Choose a lifecycle phase. The extension reads the phase spec to determine which output files are required.

3

Stub Markdown files are created at the correct paths inside your repository. Each file includes the phase objective, sections for output, risks, and approvals.

4

A notification offers to open the first created file. Fill in the actual content by running the AI prompt for that phase.

💡

The Requirements tab inside a Phase Guide also shows missing output files with a one-click Create button — a quicker alternative to scaffolding everything at once.

Webhook Queue

The webhook queue lets GitHub Actions send events to a local file-based queue, which the extension then processes to trigger the matching agent automation. This enables a lightweight local automation loop without a cloud intermediary.

Setting up the queue

1

Scaffold the GitHub workflows

Run AI DevOps: Scaffold GitHub Webhook Workflows. This writes GitHub Actions YAML files under .github/workflows/ that push events into the queue bridge endpoint.

2

Configure the bridge URL

Set the WEBHOOK_BRIDGE_URL secret in your GitHub repository. The bridge writes incoming events as JSON files into a .webhook-queue/ folder in your workspace.

3

Process queued events

Run AI DevOps: Process Webhook Queue. The extension reads each queued event, identifies the matching phase and trigger, and runs the agent automation flow automatically. Output appears in the AI DevOps Webhooks output channel.

⚠️

The webhook queue is designed for development and automation experimentation. For production workloads, use the GitHub Actions workflows directly with GitHub-managed runners.

PR Draft Generator

When the Code agent finishes implementing a feature, use the PR draft generator to produce a governance-compliant pull request body ready to paste into GitHub.

How to generate a PR draft

Run AI DevOps: Generate CODE Agent PR Draft from the Command Palette.

  1. Enter the issue or ticket reference (e.g., #123 or PROJ-456).
  2. Enter a short summary of what changed.
  3. Select the AI tool that generated the code.

The extension outputs a Markdown PR body containing:

  • Summary and related issue link
  • Implementation detail checklist
  • Tests run checklist
  • Risk assessment (functional, security, operational)
  • Rollback notes
  • AI assistance disclosure
ℹ️

Every PR created by AI must include an AI assistance section disclosing which tool was used and which prompt was referenced. This keeps the audit trail complete.

Automation Adoption Levels

The framework is designed to be adopted gradually. Match your team's current level and expand autonomy only after validating the previous level.

LevelNameWhat AI doesHuman oversight
L0 Manual Chat assistant only — no file changes Full manual control
L1 Assisted Drafts plans, docs, prompts, checklists Human reviews all drafts before use
L2 PR Automation Opens branches and PRs; human merges Humans review and approve all merges
L3 Self-Healing CI Fixes build/test/lint failures via PRs Humans merge; policy gates enforce quality
L4 Staging Autonomy Deploys to staging and validates automatically Humans approve production promotion
L5 Governed Production Triggers production under strict policy gates Policy gates; human on-call retains override
💡

Recommended starting point: L1 for new teams; L2 as the steady-state default. Only advance to L5 after strong observability, tested rollback paths, and a mature incident process are in place.

Governance Rules

These seven rules are enforced by the framework's policies and must never be bypassed — not even temporarily.

  1. AI must not push directly to protected branches. All changes go through pull requests.
  2. All code changes require a pull request — no direct commits to main or release/*.
  3. Production deployment uses protected environments with required reviewer approval gates.
  4. Secrets must never be exposed to AI prompts, logs, or output files.
  5. Every AI action must be traceable to an issue, PR, workflow run, or incident record.
  6. High-risk security findings require human security approval before remediation is merged.
  7. Rollback paths must be documented before a release or deployment proceeds.
🚫

If an AI suggestion would violate any of these rules, reject it regardless of how convenient it seems. The traceability and approval model is what makes AI-assisted delivery safe at scale.
